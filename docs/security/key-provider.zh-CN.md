# 生产密钥提供者设计

## 目标与边界

`InMemoryKeyProvider` 只用于测试和嵌入式临时场景，不能作为生产密钥托管。当前 M4 增加一个本地文件型 `FileKeyProvider`，用于单机或单写者部署：

- 密钥材料固定为 256 bit，并以 `Zeroizing<[u8; 32]>` 返回；
- 根目录和密钥文件使用受限权限，Unix 要求目录 `0700`、文件 `0600`；
- 密钥 ID 只允许稳定的 ASCII 标识，拒绝空值、路径分隔符、`.`、`..` 和控制字符；
- 每个密钥保存独立轮换元数据，版本单调递增，`rotated_from` 只引用已存在的旧 ID；
- 新文件先写入同目录临时文件、同步文件后原子发布，并在 Unix 同步父目录；
- `Debug`、错误文本和日志不包含密钥材料；
- 读取时校验固定格式、长度、ID 和权限，发现不完整文件直接失败。

该实现不等同于硬件安全模块或云 KMS：密钥仍受本机文件系统、进程内存、交换区和备份策略保护。系统 Keychain、KMS/HSM、跨主机共享、Windows 实机目录刷新和自动 Blob 加密接线不在本任务范围内。

## 文件布局

Provider 根目录下保存一个锁文件和每个密钥的二进制记录：

```text
keys/
  .lock
  <key-id>.jck
```

记录包含固定魔数、格式版本、key ID 长度、key ID、轮换版本、创建时间、前一 ID 长度、前一 ID 和 32 字节材料。材料不进入 `KeyRotationMetadata`，读取后立即复制到 `Zeroizing`。

## 轮换与恢复

写入通过锁文件串行化。Provider 先生成完整记录，再使用同目录临时文件和 `sync_all`，最后使用不覆盖已有目标的原子发布。目标已存在时返回稳定错误，不覆盖旧密钥。进程在发布前崩溃只留下临时文件；打开 Provider 时会忽略临时文件，不把半成品当作密钥。

## 接入计划

本阶段先交付 Provider 契约和本地文件存储，调用方仍显式选择 `Encryption::Aes256Gcm` 并传入 Provider 返回的密钥。后续接线必须新增配置字段和启动失败测试，禁止默认悄悄启用或把 API Key 当作加密密钥。
