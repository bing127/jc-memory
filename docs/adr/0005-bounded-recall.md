# ADR 0005：所有 Recall 必须有硬预算

- 状态：Accepted
- 日期：2026-07-30

## Context（背景）

认知图传播若没有边界，会随着数据增长退化为全图扫描，也可能因高连接节点造成不可预测的延迟和上下文膨胀。不同 Recall 意图还需要不同关系语义，不能默认穿越所有 Edge。

## Decision（决策）

每个 `RecallQuery` 必须提供 `RecallLimits`，同时限制种子数、每节点邻居数、传播跳数、总节点数和墙钟时间。候选读取在 SQLite 层按精确 Scope、可选历史截止时间和 `LIMIT` 执行。

非 `Exact` 查询合并字面 FTS5 命中与近期有界候选，再通过确定性词项、稀疏字符特征和实体匹配选择种子。传播使用全局优先队列，每个 `RecallMode` 使用显式 Edge 白名单。取消或超时返回错误，不返回伪装成完整结果的部分数据；预算丢弃候选时设置 `truncated`。

## Consequences（影响）

- Recall 的资源消耗可由调用方约束；
- Explain 和 Packet 能报告实际覆盖范围；
- 结果可能因预算较小而截断，调用方必须检查 `coverage.truncated`；
- 有界近期候选无法替代真正的向量索引，当前跨措辞能力只覆盖确定性词项和局部字符相似。

## Rejected Alternatives（否决方案）

- **按相似度扫描整个 Scope**：结果可能更全，但成本随数据量无界增长。
- **只有总节点上限**：无法限制单个高连接节点和超深路径。
- **所有模式共用全部 Edge**：容易把语义、因果、时间和执行关系混在一起。
- **超时后返回未标记部分结果**：调用方无法区分完整召回和中断结果。
